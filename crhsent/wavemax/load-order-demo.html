What actually loads on this page

A well-built page loads the tool it needs (a library called jQuery) exactly once, then runs its own code. The franchisor's franchise-recruitment page instead puts a fake placeholder in front of the real library (a speed trick), loads jQuery three times, and runs its own code against the placeholder. What you just saw — in plain terms

In the platform's real order, a placeholder stand-in for jQuery is installed first (a bolt-on speed trick). So when the page's own code runs, it calls $(…).on(…) on the placeholder — which has no such function. The browser reports Uncaught TypeError: $(...).on is not a function, and the code stops. The menu's close button and the form's submit button are never wired up — so the menu opens and won't close, and the form does nothing. The real copies of jQuery loading afterward do not help: the code that needed them already ran against the placeholder.

In the correct order, the page's code runs against the real jQuery — no placeholder in the way — the controls get wired up, and everything works. Same page, same controls; the only difference is which $ the code runs against. This is the platform's live behavior, re-verified August 21, 2026. console capture · re-verified 2026-08-21
